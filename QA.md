# Verification record

## Automated

14 tests passing using Node's built-in runner. Included 600 complete simulated journeys: 200 seeds for each of the three engines. The tested heuristic reached the terminus in all 600; this confirms reachability, not a guaranteed outcome for every strategy. Tests cover seeded determinism, input immutability, capacity, duplicate acceptance, deadlines and half fares, exact service costs, advance repayment, event gating, invalid saves, terminus unloading, timeout and retirement, affordable incident choices, crew fees, and unique platform roles.

Production distribution is generated by `npm run build` with no external dependencies.

## Browser checks performed

- Started the game and boarded contracts.
- Reloaded and continued the saved journey; passengers and resources persisted.
- Completed an entire eight-station journey on desktop.
- Completed a second entire journey at a 390×844 responsive viewport after crew costs and role uniqueness were added.
- Exercised incidents, refuelling, repairs, arrivals, on-time and late payouts, endings, and same-seed replay.
- Opened and closed the guide and export dialog.
- Confirmed that the export image renders at 1200×720 pixels.
- Inspected the desktop and narrow layouts; narrow document width did not exceed the viewport.
- No browser console errors or warnings were reported during the completed runs.

## Verification limitation

The in-app browser's download-event automation timed out for the original automatic download. Export was changed to show the generated image in a dialog with a direct download link and manual image-save fallback. Image generation and preview were verified; automatic download completion in this particular embedded browser is not claimed.

No real-customer playtests, revenue tests, or exhaustive cross-browser checks have been performed.

## Storefront integration

Automated server tests cover server-controlled price and origin validation, rejection of unpaid/wrong-product/live/refunded purchases, concurrent durable fulfillment, signed download authorization, refund rechecks, actual Stripe SDK webhook signature verification, duplicate notifications, webhook fulfillment without a return visit, and private-path isolation. Stripe API responses are mocked; no hosted Stripe test transaction or live payment has been performed. The server is deliberately test-mode-only. Email fulfillment and production deployment remain outstanding.

Browser verification: opened the storefront, confirmed checkout is disabled without credentials, entered the demo, accepted/delivered two contracts, resolved an incident, and reached the third-station completion screen. No console errors were recorded in that flow. Storefront layout was visually inspected at the browser's current viewport. Mobile layout and actual hosted Stripe checkout have not yet been verified for this change.
